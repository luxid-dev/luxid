# 19 — OpenAPI

An OpenAPI document describes your API in a format tools understand: Swagger UI,
Postman, client generators for a dozen languages. Luxid builds one from your
code.

## Getting one

```sh
cargo run -- openapi > openapi.json
cargo run -- openapi --pretty --title "Blog API" --version 1.0.0
```

Every registered route appears, whether or not you documented it.

## Documenting an action

```rust
#[luxid::controller]
impl PostsController {
    #[openapi(summary = "List posts", tag = "posts", ok = PageOfPosts)]
    async fn index(ctx: HttpContext) -> Result<Response> { /* ... */ }

    #[openapi(tag = "posts", ok = PostView, errors = [404])]
    async fn show(ctx: HttpContext) -> Result<Response> { /* ... */ }

    #[openapi(body = StorePost, created = PostView, errors = [422, 409])]
    async fn store(ctx: HttpContext) -> Result<Response> { /* ... */ }

    #[openapi(no_content, errors = [404])]
    async fn destroy(ctx: HttpContext) -> Result<Response> { /* ... */ }
}
```

| Key | Meaning |
|---|---|
| `summary = "..."` | One-line description |
| `tag = "..."` | Groups related endpoints |
| `body = T` | Request body schema |
| `ok = T` | 200 with this schema |
| `created = T` | 201 |
| `accepted = T` | 202 |
| `no_content` | 204, no body |
| `errors = [422, 404]` | Which failures this endpoint produces |

## Types need `JsonSchema`

Any type named in `body`, `ok`, `created` or `accepted` must derive it:

```rust
use luxid::JsonSchema;
use serde::Serialize;

#[derive(Serialize, JsonSchema)]
pub struct PostView {
    pub id: i64,
    pub title: String,
}
```

Generated form requests already derive it. Note that a generated app declares
`schemars` directly in its `Cargo.toml` — the derive emits `schemars::` paths, so
re-exporting it through `luxid` is not enough for `#[derive(..)]` to resolve.
`luxid new` sets this up for you.

## What you get for free

**Error schemas.** You write `errors = [422]`; the document gets a
`application/problem+json` response referencing a shared `Problem` component,
with the field-error map described. You never write that shape.

**Path parameters.** `/posts/{id}` produces the `id` parameter automatically,
derived from the route pattern — so it can never disagree with the route.

**Operation ids.** Each operation is identified as `PostsController::show`, which
client generators turn into method names.

## Undocumented actions still appear

An action with no attribute is present but bare:

```json
"/api/health": {
  "get": {
    "operationId": "HealthController::show",
    "responses": { "default": { "description": "Undocumented" } }
  }
}
```

Omitting it would make the document quietly lie about what your API exposes. A
marked-undocumented endpoint is honest; a missing one is not.

## OpenAPI 3.1

Luxid emits 3.1 rather than 3.0 because **3.1 *is* JSON Schema**. Schemas
generated by `schemars` drop in unchanged rather than being translated into
3.0's near-miss dialect.

Most modern tooling handles 3.1. If yours does not, a converter is easier than
degrading the schemas.

## Serving the document

```rust
pub struct DocsController;

#[luxid::controller]
impl DocsController {
    async fn openapi(ctx: HttpContext) -> Result<Response> {
        // Embedded at build time by `cargo run -- openapi > openapi.json`.
        ctx.response
            .header("content-type", "application/json")
            .text(include_str!("../../openapi.json"))
    }
}
```

Generating it in CI and committing the result also gives you a reviewable diff
when your API surface changes — which is often exactly the review you want.

## Keeping it honest

The attribute restates types the body already mentions, so it can drift. Two
habits help:

- **Regenerate in CI** and fail if `openapi.json` changed without being
  committed. A drifted document is worse than none.
- **Document errors as you add them.** When you add a `Conflict` to an action,
  add `409` to its `errors` list in the same commit.

## Why the route table, not a registry

Some frameworks collect documentation into a global registry at startup, using
linker tricks. Luxid walks the **route table** instead — the same explicit
registration a request goes through.

The practical consequence: a route missing from your document is a route missing
from `cargo run -- routes`. There is no third place where an endpoint might be
hiding.
